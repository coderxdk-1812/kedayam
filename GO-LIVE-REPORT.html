🚧 Gaps to Go Live on the Chrome Web Store

Blocker Stale package artifact — fails its own checksum

Shipped public/kedayam.zip is 119,718 bytes / sha db0b6e4f…, but kedayam-release-cert.json certifies 98,768 bytes / sha dd9b355b…. The zip was built 2026-05-25 and the cert dated 2026-05-20 — both predate later commits (Stabilized clone detection, XSS toast fix, etc.). Rebuild and re-certify before uploading: bun run build:extension → scripts/release-certify.mjs.

Blocker No publicly-hosted Privacy Policy URL

The store dashboard requires a live HTTPS URL to a privacy policy. A PRIVACY.md in the repo does not satisfy this — host it (GitHub Pages, the project site, or Cloudflare) and paste the URL into the listing. Content is already written; only hosting is missing.

Blocker No store listing assets (screenshots / promo tiles)

Chrome requires at least one screenshot (1280×800 or 640×400) and a 440×280 small promo tile. None exist in the repo (no screenshots/ or promo images found). Capture popup, options, and a live detection overlay; produce the promo tile. The 1280×800 marquee is optional but recommended.

Required Registered developer account + data-use disclosures

Needs a Chrome Web Store developer account (one-time $5 fee + identity verification), plus the in-dashboard single-purpose description, permission justifications, and the data-handling / privacy practices certification. Source material is ready in PERMISSIONS.md; it must be re-entered in the dashboard forms.

Required Broad-permission review will be triggered

host_permissions: http://*/*, https://*/* plus tabs, webRequest, and webNavigation place this in Chrome's extended review track (longer approval, stricter scrutiny). It is justifiable for a security tool — make sure the dashboard justification mirrors PERMISSIONS.md and expect a slower first review. Consider whether activeTab-only flows can narrow any of this.

Recommended Add a LICENSE file

No LICENSE in the repo. Not strictly required by the store, but expected for an "auditable, open" security extension whose docs invite source review.

Recommended Production console-logging polish

logger.js emits console.info/warn/error in production (not dev-gated). Harmless but noisy; gate to warn+ or behind a flag for a cleaner reviewer impression.

Recommended CI + E2E coverage

No .github/workflows/ and an empty tests/e2e/. Add a CI job running validate → test → certify on every push, and at least one Playwright smoke test, so the certified artifact can never drift from source again (the exact failure seen above).

Recommended Verify production build flags

window.__kedayam dev global is gated on absence of update_url. Confirm the Web-Store-signed build carries update_url so dev hooks stay disabled; smoke-test the packaged zip as an unpacked load before upload.
