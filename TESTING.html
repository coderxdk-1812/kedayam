1. What's in the repo (and what to load)

For day-to-day testing you load the unpacked source folder (extension/) — you do not need any zip. The zips exist only for store submission and for testing the exact packaged bytes.

ArtifactWhat it isIn git?Load it for…
extension/ Unpacked MV3 source — the real extension tracked All Chromium browsers (dev testing) — use this
public/kedayam.zip Packaged Chrome / Web-Store artifact committed Testing the exact store bytes
public/kedayam-chrome.zip Chrome build (identical to store zip) build output Chrome Web Store upload
public/kedayam-edge.zip Microsoft Edge build build output Edge Add-ons upload
public/kedayam-firefox.zip Firefox build (adds browser_specific_settings.gecko) build output Firefox AMO upload / about:debugging

The three cross-browser zips are .gitignored because they're reproducible build outputs. If you just cloned the repo and they aren't in public/, build them — see the next section. (In this working tree they're already present and current at v1.1.3.)

2. Building the packages (if missing)

Requires Node ≥ 20 and Bun. From the repo root:

# install deps once
bun install

# Chrome/Web-Store zip → public/kedayam.zip
bun run build:extension

# Chrome + Edge + Firefox zips → public/kedayam-{chrome,edge,firefox}.zip
bun run build:crossbrowser

# (optional) checksum + release cert + drift gate
node scripts/release-build.mjs && node scripts/release-certify.mjs
node scripts/verify-artifact.mjs

No build is needed to load the unpacked extension/ folder — the source is already runnable. Build only when you want the packaged zips.

3. Load in Chrome / Edge / Brave / Opera / Arc / Vivaldi

All Chromium browsers use the same build. The address differs slightly per browser:

BrowserExtensions page
Chromechrome://extensions
Edgeedge://extensions
Bravebrave://extensions
Operaopera://extensions
Vivaldivivaldi://extensions
ArcMenu → Extensions → Manage Extensions

Steps

  1. Open the extensions page for your browser (table above).
  2. Turn on Developer mode — the toggle is in the top-right corner (Chrome/Brave/Vivaldi) or the left sidebar (Edge).
  3. Click Load unpacked and select the extension/ folder (the one containing manifest.json) — select the folder itself, don't go inside it.
  4. Pin it: click the puzzle-piece 🧩 in the toolbar, then the pin next to Kedayam Browser Shield.
Prefer to test the packaged zip instead of the source? Unzip public/kedayam.zip to a folder first, then Load unpacked that folder. Chromium can't load a .zip directly in dev mode.

4. Load in Firefox

Firefox loads a temporary add-on that lasts until you close the browser.

  1. Open about:debugging#/runtime/this-firefox.
  2. Click Load Temporary Add-on…
  3. Select public/kedayam-firefox.zip (or the manifest.json inside the extension/ folder).
  4. The extension appears under "Temporary Extensions". Use the toolbar icon to open the popup.
Use the Firefox zip, not the Chrome one. Only kedayam-firefox.zip carries the browser_specific_settings.gecko id Firefox requires. MV3 background-ESM support also varies by Firefox version — this build is packaged but not yet fully runtime-validated on Firefox; if the background service worker misbehaves, that's the known caveat, not your setup.

Optional lint before AMO submission: npx web-ext lint --source-dir extension.

5. Verify it loaded correctly

  • The card shows Kedayam Browser Shield — 1.1.3 with no red "Errors" button.
  • Toolbar icon is visible (pin it if not).
  • Click the icon on any http(s) page → the popup opens and shows a trust score plus an explanation (not "UNAVAILABLE").
  • The popup footer reads v1.1.3.

7. Reloading after code changes

Edited something under extension/? You don't need to remove and re-add it:

  • Chromium: go to the extensions page and click the ↻ reload icon on the Kedayam card (or press R while the card is focused). Then reload the page you're testing.
  • Firefox: in about:debugging, click Reload next to the temporary add-on.
  • Changed the manifest, permissions, or the background worker? A full reload of the extension (not just the page) is required — the reload icon covers this.

8. Troubleshooting

"Cannot load extension with file or directory name _metadata"

macOS/Chrome sometimes drops a stray _metadata/ folder (containing only a .DS_Store) inside the extension dir. Filenames starting with _ are reserved, so the load fails. Delete it and reload: 

rm -f extension/_metadata/.DS_Store && rmdir extension/_metadata

Popup says "UNAVAILABLE" / score won't load

Fixed in v1.1.1 (large Chrome tab-ids were rejected). Confirm the card reads 1.1.3; if it shows an older version you're loading a stale copy — remove it and load the current extension/ folder. The popup only scores http(s) tabs, not chrome:// / about: pages (a URL-only fallback is shown there).

"Errors" button is red on the card

Click it to read the message, then re-run bun run validate:extension which checks the manifest, CSP, and web-accessible resources. A clean tree passes with "Kedayam extension valid."

Developer-mode warning on Chrome restart

Expected for any unpacked extension — just dismiss "Disable developer-mode extensions".

Firefox: background worker not running

Known caveat — MV3 background-ESM support varies by Firefox version. The Firefox build is packaged but not yet fully runtime-validated (see STATUS.html). Content-script guards still work; the popup may differ.
